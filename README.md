# platform-agent-kit

Набор правил и навыков агентов (Claude Code и OpenCode) для работы платформенного инженера: Helm-чарты,
экспортеры на Python, работа с внешними API и Yandex Cloud, дашборды Grafana любого вида. В кит входит только
то, что уже обкатано в работе.

Агенту: чтобы поставить или обновить кит в проекте или во всех проектах папки, следуй `INSTALL.md`.

Статус: версия 1 готова — ядро, установщик и пять профилей (спецификация `docs/specs/001-kit-v1.md`).
Профиль `terraform` — спецификация `docs/specs/003-terraform-profile.md`, `gitlab-ci` —
`docs/specs/004-gitlab-ci-profile.md`, `fluxcd` — `docs/specs/006-fluxcd-profile.md`.
Дальше — профили-заготовки по интервью и перевод существующих проектов на кит, план в `TASKS.md`.

## Как устроен

- **Ядро** ставится всегда: общие правила, подход к доработкам (спецификация → задача → тест → код,
  ветки, мерж после проверки), шаблоны `docs/specs/` и `TASKS.md`, команды ревью для OpenCode.
- **Профили** добавляют правила и навыки под вид работы. Профиль может требовать другой — установщик
  добавит его сам.
- **Сторонние навыки** не хранятся в ките: в ядре и профилях только ссылки с закреплённым коммитом,
  ставит их установщик через CLI `skills`.

Подробнее о раскладке и принятых решениях — `docs/00-overview.md`.

## Установка в проект

Проще всего — агентом: «поставь кит из https://github.com/alexwirehead/platform-agent-kit» в проекте
или «поставь кит во все проекты в `~/projects`». Агент сам выберет профили по признакам проекта,
неясное спросит и ничего не закоммитит; порядок — `INSTALL.md` (спецификация
`docs/specs/005-agent-install.md`). Руками:

Нужны `bash` (подходит 3.2 из macOS), `git` и `npx` (Node.js) — через него ставятся сторонние навыки.

1. Склонировать кит в любой каталог, например рядом с проектами (решения К8 и К11):

   ```bash
   git clone git@github.com:alexwirehead/platform-agent-kit.git ~/projects/platform-agent-kit
   ```

   Путь ничем не закреплён: установщик находит свой каталог сам. Ниже в примерах — `~/projects`.

2. Поставить в проект ядро и нужные профили:

   ```bash
   ~/projects/platform-agent-kit/install.sh <каталог-проекта> helm python-exporter
   ```

   Список профилей с описаниями — `install.sh --help`.

3. Заполнить в `AGENTS.md` проекта раздел «Project» (создаётся, если `AGENTS.md` не было): где журнал
   решений и какая команда полной проверки.
4. Закоммитить результат. Навыки (`.agents/`, `.claude/skills/`) в git не идут — установщик сам
   дописывает их в `.gitignore`.

Что появится в проекте:

| Что | Где |
|---|---|
| правила ядра и профилей, таблица «ситуация → навык», пункты ревью | `AGENTS.md`, блок между `<!-- platform-agent-kit:begin -->` и `<!-- platform-agent-kit:end -->` |
| импорт для Claude Code | `CLAUDE.md` с `@AGENTS.md`, если файла не было |
| навыки | `.agents/skills/`, для Claude Code — симлинки в `.claude/skills/` |
| команды `simplify`, `code-review`, `security-review` для OpenCode | `.opencode/commands/` |
| шаблоны процесса и профилей | `TASKS.md`, `docs/specs/README.md` и другие — только если файла нет |
| версия кита, профили, навыки | `.agent-kit.lock` |

## Обновление и смена профилей

```bash
git -C ~/projects/platform-agent-kit pull
~/projects/platform-agent-kit/install.sh <каталог-проекта> <профили>
```

Повторный запуск с тем же списком ничего не меняет. Блок в `AGENTS.md` заменяется целиком, текст вне
блока не трогается. Если профиль убрать из списка, его навыки и правила удалятся. Шаблоны остаются:
это уже файлы проекта, и удалённый проектом шаблон обратно не ставится.

## Правила проекта поверх кита

- Свои правила и отступления от правил кита — в `AGENTS.md` вне блока, с причиной.
- Файлы кита в проекте не правятся: блок и навыки перезапишутся при обновлении. Улучшение правила —
  доработка в самом ките.
- Свой навык проекта кладётся настоящим каталогом в `.claude/skills/<имя>/`. Если имя совпадает
  с навыком кита, побеждает навык проекта. Установщик добавит для него исключение
  `!.claude/skills/<имя>/` в `.gitignore`.

## Расход контекста

Сколько токенов в проекте занимают правила и навыки:

```bash
uv run ~/projects/platform-agent-kit/scripts/count-tokens.py <каталог-проекта>      # оценка
uv run ~/projects/platform-agent-kit/scripts/count-tokens.py <каталог-проекта> \
  --hf zai-org/GLM-5.3-Flash                                                       # токенизатор модели
```

Нужен только `uv`: зависимости скрипт ставит сам, первый запуск качает токенизатор. В проект скрипт
ничего не пишет. `--hf` принимает репозиторий модели на Hugging Face или путь к `tokenizer.json`.
Без `--hf` считает `o200k_base`; на текстах кита он расходится с GLM-5.3-Flash на 1–2%.

```
Всегда в контексте:
  AGENTS.md                         2535
  skill list                        1229   frontmatter 17 навыков, на каждом шаге
  total                             3764

Навыки: body — при загрузке, files — если дочитать всё, front — в списке навыков
  skill                             body   files  front
  docker-patterns                   3947       0     63
  ...
```

- **Всегда в контексте** — `AGENTS.md` и список навыков (имя и описание каждого). Модель видит их на
  каждом шаге, и сжатие контекста их не убирает.
- **body** — тело `SKILL.md`. Добавляется в переписку при загрузке навыка и пропадает при сжатии.
- **files** — остальные текстовые файлы навыка: справочники, примеры, скрипты. Это верхняя граница:
  агент читает их, только когда навык велит.

Чем меньше окно модели, тем раньше наступает сжатие. Лишний профиль увеличивает и постоянную часть, и
то, что агент загрузит по ходу работы.

## Разработка кита

- Порядок работы для агента и человека — `AGENTS.md`: спецификация `docs/specs/NNN-slug.md`, решение
  в `docs/00-overview.md`, задача в `TASKS.md`, ветка `feature/NNN-slug`, мерж после проверки.
- Окружение — девконтейнер, см. `.devcontainer/README.md`.
- Кит работает по своему ядру (решение К12). После клона и после каждого изменения `core/` —
  `./install.sh .` в корне кита: он ставит навыки ядра и обновляет блок в `AGENTS.md`. Устаревший
  блок ловит тест `test_kit_agents_block_up_to_date`.
- Проверка перед коммитом:

  ```bash
  uv run pytest                       # тесты установщика, scripts/ и shellcheck
  uv run ruff check && uv run ruff format --check
  ```

  Совместимость установщика с bash 3.2 проверяется прогоном `uv run pytest` на маке.
- Сторонний навык поднимается на новый коммит только после чтения его diff (решение К3).

## Язык

Тексты для агента (`SKILL.md`, фрагменты правил, команды) — на английском: так меньше контекста
(русский текст навыка выходит примерно на 19% дороже, замер в решении К5).
Документы для людей — на русском.
