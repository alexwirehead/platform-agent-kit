# Профиль gitlab-ci

Пайплайны и компоненты CI/CD GitLab 18.11: оценка, нужен ли компонент, перевод старых шаблонов в компоненты.

- Навык `gitlab-ci-components`. Компонент делается, только если шаблон нужен как минимум в двух проектах
  уже сейчас, различия укладываются в `spec:inputs` и интерфейс стабилен; иначе шаблон остаётся локальным.
  Разросшийся YAML — не повод для компонента: логика уходит в `.gitlab/ci/scripts/`, пайплайн делится на
  `.gitlab/ci/*.yml`. Рефакторинг — сначала таблица оценки, её согласует пользователь, потом перенос
  по одному шаблону.
- Репозиторий компонента: свой у каждого, проект CI/CD Catalog, `templates/<name>/template.yml`, свой
  образ `:X.Y.Z` в том же репозитории, пайплайн подключает сам компонент, релиз на тег `X.Y.Z` джобом
  `release`. Потребители подключают `@1` или `@1.2`.
- Проверки: `dev/check-ci.sh` офлайн (yamllint, схема GitLab CI, shellcheck), затем `glab ci lint` — его
  агент запускает сам, только чтение (К14).
- Шаблон (кладётся, если файла нет): `dev/check-ci.sh`.
- Пункты ревью: оценка компонента, `description` у inputs, логика вне `script:`, тег образа, версия у
  потребителя, секреты.

Нужны: `yamllint`, `check-jsonschema`, `shellcheck`, `glab`.
