## Зачем

Обкатанные правила и навыки нужны во всех проектах: отдельные Helm-чарты, пайплайны,
экспортеры, работа с API. Копировать `AGENTS.md` руками нельзя: копии расходятся, и улучшения не
доходят до остальных проектов. Запрос пользователя от 2026-10-24.

## Что меняется

### Ядро (ставится всегда)

`core/rules.md` — общие правила, `core/skills.md` — строки таблицы «ситуация → навык»:

- простое лучше сложного; после задачи с кодом — `simplify`;
- никаких придуманных фактов: API библиотек — `source-driven-development`, факты о внешних системах —
  профиль `external-api`;
- тесты без девконтейнера: окружение передаётся параметром, файлы в `tmp_path`, абсолютных путей нет;
- секреты не логируются и не коммитятся, реальных ID в репозитории нет;
- решения проекта не пересматриваются молча; уточняющие вопросы — без напоминания, с вариантами,
  рекомендуемый первым;
- навык загружается только в своей ситуации и не больше одного раза за сессию;
- язык: документы и docstring на русском; код, имена, логи на английском;
- коммиты по Conventional Commits (К9): тип и scope на английском, описание на русском.

Навык `change-workflow` — подход к доработкам: спецификация `docs/specs/NNN-slug.md` → задача
в `TASKS.md` со строкой «Спека:» → падающий тест → код → перенос изменения в документы текущего
состояния. Статусы задач `[ ]`, `[~]`, `[x]`, `[!]`; ветки `feature/NNN-slug`, `fix/<slug>`,
`docs/<slug>`; мерж `--no-ff` только после подтверждения пользователя, для кода — после проверки на
реальном окружении.

Шаблоны `core/templates/`: `docs/specs/README.md` (порядок и шаблон спецификации), `TASKS.md`.

Команды OpenCode `simplify`, `code-review`, `security-review` (EN) без привязки к Yandex Cloud: проверки
конкретной области уходят в `profiles/<имя>/review.md`, установщик собирает их в раздел «Review checks»
блока `AGENTS.md`, и команды ссылаются на этот раздел. Формат команд — https://opencode.ai/v2/docs/commands.

Сторонние навыки ядра: `test-driven-development`, `verification-before-completion`,
`systematic-debugging` (obra/superpowers), `source-driven-development` (addyosmani/agent-skills),
`ru-text`, `no-ai-slop`. Коммиты закреплены, как в К3.

### Установщик

`install.sh <каталог> [профиль...]`:

1. Проверяет имена профилей и добавляет зависимые. Профиль — каталог `profiles/<имя>/`, все его файлы
   необязательны. Проверяет маркеры `AGENTS.md`: оба по одному отдельной строкой и по порядку или оба
   нет; иначе ошибка до любой записи. CRLF не мешает.
2. Собирает блок `AGENTS.md` (К7), включая раздел «Review checks» из `review.md` профилей; если `AGENTS.md` нет, создаёт его с заготовкой раздела проекта:
   где журнал решений, какая команда полной проверки.
   Создаёт `CLAUDE.md` с `@AGENTS.md`, если его нет.
3. Копирует свои навыки в `.agents/skills/`, ставит сторонние через CLI `skills`, делает симлинки
   в `.claude/skills/`. Навыки профилей, убранных из списка, удаляет.
4. Кладёт команды в `.opencode/commands/`, шаблоны — только если файла нет.
5. Дописывает в `.gitignore` строки для `.agents/` и `.claude/skills/*`, если их нет, и исключение
   `!.claude/skills/<имя>/` для каждого своего навыка проекта (настоящий каталог, не симлинк кита).
6. Пишет `.agent-kit.lock`: коммит кита, профили, установленные навыки. Даты нет: иначе повторный
   запуск менял бы файл.

Профиль, от которого зависит другой, перечислен в его файле `requires`. Установщик работает на bash 3.2
(macOS) и на GNU/Linux. Повторный запуск с тем же списком ничего не меняет. Флаг `--offline` пропускает сторонние навыки:
им пользуются тесты.

## Что не меняется

- Существующие проекты в этой спецификации не трогаются. Перевод их на кит — отдельная спецификация
  в каждом проекте (T5.2).
- Профили-заготовки (`cicd`, `fluxcd`, `argocd`, `otel`, `monitoring`) — вне v1, этап 4.
- Не делаем плагин Claude Code, свой CLI, удалённую публикацию кита.

## Готово, когда

- `tests/run.sh` проходит: установка в пустой каталог `--offline` с каждым профилем, повторный
  запуск без изменений (`git status` целевого чистый), смена списка профилей убирает лишние навыки,
  правила проекта вне блока сохраняются.
- `shellcheck install.sh tests/*.sh` без замечаний.
- Установка в чистый проект с сетью: навыки видны в Claude Code (`/skills`) и в OpenCode.
- В ките нет внутренних адресов, реальных ID и упоминаний заказчиков и исходных проектов.
