# 013. План задачи в файле и известные ошибки агента

Статус: принята 2026-11-27, пользователь
Задачи: T1.8 [~], T1.9 [~]
Решения: К23

## Зачем

Пользователь (2026-11-27) предложил взять две практики из «The AI-native SDLC playbook» Anthropic
(Louis Claxton, 2026-08-21, https://claude.com/resources/articles/the-ai-native-sdlc-playbook):

- **план до кода в файле.** Агент записывает, какие файлы трогает, в каком порядке и какими тестами
  проверяет. Если реализация разошлась с планом, план правится в том же коммите. Для GLM это важно:
  файл переживает сжатие контекста, как уже переживает спека (К17, К21);
- **«одна ошибка дважды — правка в правилах».** Повторную ошибку агента записывают одной строкой в
  `AGENTS.md`, чтобы она не повторилась в следующей сессии.

Ответы пользователя на интервью: план — отдельный файл на спеку; отдельной остановки для плана нет, его
видно в diff на остановке 2; запись об ошибке агент предлагает, пишет только после «да».

## Что меняется

### План

- Порядок `change-workflow`: **спека → задача → план → падающий тест → код → документы → merge
  request**. Так же — в правиле 7 ядра.
- После принятия спеки и заведения задач агент пишет `docs/specs/NNN-slug.plan.md`, один на спеку: по
  разделу на задачу, в каждом файлы, порядок шагов и тесты, которые сначала упадут. Шаблон плана — в
  `docs/specs/README.md`.
- Код разошёлся с планом — план правится в том же коммите. Сделанный шаг отмечается.
- Новой остановки нет: план попадает в diff первого коммита задачи (остановка 2).
- «Starting a session», шаг 4: вместе со спекой агент читает её план. После сжатия правда — файл плана,
  а не сводка.
- Спека сделана — план, как и спека, больше не правится.
- Работа без спеки идёт без плана.

### Известные ошибки

- Новое правило ядра: пользователь второй раз поправил одну и ту же ошибку — агент предлагает строку в
  список `Known mistakes` раздела проекта `AGENTS.md`: что идёт не так и как правильно. Пишет только
  после «да» пользователя, одна строка на ошибку.
- `install.sh` в новом `AGENTS.md` пишет пустой подраздел `### Known mistakes` в разделе проекта. В
  существующем проекте агент заводит его, когда появится первая запись.

### Этап 6, идеи на потом

Дописать в `TASKS.md` идеи плейбука, которые не берутся сейчас, рядом с идеями IDSD:

- в шаблоне `review.md` деление находок на важные и мелкие, не больше пяти мелких за ревью;
- регрессионные сценарии кита из реальных сбоев (GLM теряет порядок после сжатия, агент лезет в
  репозиторий кита без установки, память подсовывает старые правила) — прогон после правок `core/`;
- запрет push и мержа механическими правами (Claude Code `permissions.deny`, OpenCode `permissions`):
  плейбук считает навык рекомендацией, а не принуждением. Это пересмотр К21, только по решению
  пользователя;
- T6.2 дополнить: падающий тест коммитится до кода, агент его не правит (тот же вывод в плейбуке).

## Что не меняется

- Две остановки К21, их место и смысл.
- Формат спеки: «Как» по-прежнему не в спеке, а в плане и коде.
- Из плейбука не берём: auto mode без подтверждений, параллельные сессии в worktree, `claude -p` в CI,
  отдельный intent.md (его закрывает «Зачем»), всё, что завязано на продукты Anthropic.
