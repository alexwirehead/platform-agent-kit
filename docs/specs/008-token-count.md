# 008. Подсчёт токенов: сколько контекста съедают правила и навыки

Статус: сделана 2026-11-13
Задачи: T5.10 [x], T5.3 [x]
Решения: К18

## Зачем

Пользователь (2026-11-13): слабая модель с маленьким окном (GLM-5.3-flash в OpenCode) часто сжимает
контекст. Нужно видеть, сколько токенов в проекте всегда занято правилами и сколько стоит загрузка
каждого навыка, чтобы решать, какие профили и навыки ставить. Заодно закрыть T5.3: замер одного навыка
на русском и на английском для К5.

## Что меняется

Скрипт `scripts/count-tokens.py` в ките, запуск из клона кита:

```bash
uv run scripts/count-tokens.py <проект>                    # оценка, токенизатор o200k_base
uv run scripts/count-tokens.py <проект> --hf <репо|tokenizer.json>  # токенизатор модели
```

Зависимости — в самом скрипте (inline metadata, `uv run`); dev-зависимости кита не меняются.
Первый запуск качает токенизатор, дальше из кэша.

Вывод:

- всегда в контексте: `AGENTS.md` проекта и список навыков — сумма frontmatter (`name`, `description`)
  всех навыков: агент видит его на каждом шаге;
- таблица навыков, по убыванию тела: тело `SKILL.md` (при загрузке), остальные текстовые файлы папки
  навыка (верхняя граница, если агент дочитает всё), frontmatter;
- итог по колонкам.

Навыки — из `.agents/skills/` и `.claude/skills/` проекта, одна папка считается один раз (симлинки).
Ничего не пишет в проект.

README: раздел «Расход контекста» — как запустить, что значат колонки, что цифры o200k_base — оценка,
точные — с `--hf`.

T5.3: навык `change-workflow` переводится на русский только для замера (в кит не попадает), обе версии
считаются o200k_base и токенизатором GLM; результат — в К5.

## Что не меняется

- Установщик и проекты: скрипт в проекты не ставится.
- Точный счёт для Claude (`count_tokens` API) — не в скрипте: нужен ключ.
- Язык текстов для агента (К5) — замер только записывается.

## Затронутые документы

- `README.md` — раздел «Расход контекста», строка в «Разработка кита» про `scripts/`.

## Готово, когда

- Тест на временном проекте с подменённым счётчиком: `AGENTS.md`, frontmatter, тело, прочие файлы,
  симлинк считается один раз, двоичный файл пропускается, порядок по убыванию тела.
- `uv run scripts/count-tokens.py .` на ките и на установке с профилями печатает таблицу.
- `--hf` с токенизатором GLM работает (если репозиторий токенизатора доступен).
- `uv run pytest && uv run ruff check && uv run ruff format --check` чистые.
