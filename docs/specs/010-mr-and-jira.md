# 010. Мерж делает человек через MR, ключ Jira в ветке и коммите

Статус: принята
Задачи: T1.6 [ ]
Решения: К20

## Зачем

Пользователь (2026-11-18): навык `change-workflow` велит агенту мержить ветку самому
(`git merge --no-ff` после подтверждения). В проектах так нельзя: мерж делает человек через merge
request в GitLab. Коммиты в командах пишутся с ключом тикета Jira, а описания коммитов у агентов
многословные.

## Что меняется

**Ветка и MR** (`change-workflow`, раздел 5):

- Имя ветки — `<type>/<KEY>-<slug>`: `feature/PROJ-123-node-group-presets`; `<type>` — `feature`, `fix`
  или `docs`. Номер спецификации в имени ветки больше не нужен.
- Ключ Jira — из просьбы пользователя или имени текущей ветки. Не нашёл — спросить до создания ветки, не
  выдумывать. Пользователь сказал, что тикета нет, — ветка и коммиты без ключа.
- Агент не делает `push`, не создаёт MR и не мержит. Ветка готова — коммит и чистая полная проверка;
  агент даёт заголовок MR (как заголовок коммита) и короткое описание: что и зачем, как проверено,
  ссылка на спецификацию. Push, MR и мерж — человек.
- В заметках задачи `Ветка: <имя>`, как сейчас.
- Порядок этапов: spec → task → failing test → code → docs → merge request.

**Сообщение коммита** (`core/rules.md`, «Commit messages»):

- `<type>(<scope>): <KEY> <description>`, пример `chore(variables): PROJ-123 изменён node_group_presets`.
  Ключ — из имени ветки.
- По умолчанию только заголовок, до 72 символов. Тело — до трёх строк и только если причина не видна из
  diff; без списка файлов и пересказа diff. Подробности — в описании MR.
- Футеры `Задача: T2.2` и `BREAKING CHANGE:` остаются.

**Кит** — отступление в разделе проекта `AGENTS.md`: Jira нет, ветки `feature/NNN-slug`, коммиты без
ключа; мерж — PR на GitHub пользователем, как сейчас.

## Что не меняется

- Остальной Conventional Commits (К9): типы, scope, язык.
- Спецификация `docs/specs/NNN-slug.md`, задачи и футер `Задача:`.
- Агент по-прежнему не ходит в GitLab на запись.

## Готово, когда

- Тест: в навыке нет `git merge`, порядок этапов совпадает с правилом 7, в «Commit messages» формат с
  `<KEY>` и предел тела.
- `uv run pytest && uv run ruff check && uv run ruff format --check` чистые.
- Пользователь проверил в проекте: агент берёт ключ из ветки, коммит в одну строку, вместо мержа даёт
  текст MR.
