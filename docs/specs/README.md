# Спецификации доработок и исправлений

Каждое изменение поведения описывается отдельным файлом здесь, до задачи и до кода (навык
`change-workflow`). `README.md`, `docs/00-overview.md` и файлы `core/`, `profiles/` описывают, как кит работает сейчас. Спецификация
описывает изменение: что, зачем и как проверить.

## Порядок

1. Создать `NNN-slug.md` по шаблону ниже: следующий свободный номер, короткое имя на английском
   (`002-cicd-profile.md`). Статус «черновик».
2. Если по ходу принято решение, оно идёт в `docs/00-overview.md`, раздел 4, а в спецификации
   остаётся ссылка.
3. Спецификация согласована — статус «принята», завести задачу или задачи в `TASKS.md`. В задаче
   строка `Спека: docs/specs/NNN-slug.md`, в спецификации задача в поле «Задачи».
4. Задача делается по спецификации. В неё же входит перенос изменения в текущие документы и файлы кита
   (разделы перечислены в «Затронутые документы»).
5. Все задачи закрыты — статус «сделана» с датой, отметки задач в шапке обновлены. Файл не удаляется
   и дальше не правится: это история изменения.

Спецификация не нужна для исправления кода под уже описанное поведение, рефакторинга без изменения
поведения, опечаток и правок документации.

## Шаблон

```markdown
# NNN. Название

Статус: черновик | принята | сделана ГГГГ-ММ-ДД
Задачи: T0.0 [ ]
Решения: Р0 (если есть)

## Зачем

Проблема или запрос, кто просил.

## Что меняется

Поведение после изменения: конфиг, метрики, правила, ошибки, логи. Примеры.

## Что не меняется

Границы: что сознательно не трогаем.

## Затронутые документы

Куда перенести изменение после выполнения: файл и раздел.

## Готово, когда

Проверяемые критерии: тесты, команды, стенд.

## Открытые вопросы

Пусто, если нет. Неотвеченный вопрос не даёт перевести спецификацию в «принята».
```
