# 007. Порядок изменения переживает сжатие контекста

Статус: сделана 2026-11-13
Задачи: T1.5 [x]
Решения: К17

## Зачем

Пользователь заметил (2026-11-13): GLM-5.3-flash в OpenCode начинает изменение по `change-workflow`, а в
длинной сессии теряет этапы — тест, `TASKS.md`, ветку.

Причина по документации OpenCode: текст навыка попадает в переписку
(https://opencode.ai/docs/skills.md, «Loading»), при сжатии старая переписка заменяется сводкой и
последними ~15k токенов, а файлы инструкций остаются (https://opencode.ai/docs/compaction.md). После
сжатия навыка в контексте нет, а правило ядра «Do not load the same skill twice in a session» запрещает
загрузить его снова. У модели с маленьким окном сжатие частое.

## Что меняется

В `core/rules.md`, то есть в блоке `AGENTS.md`, который всегда в системном промпте:

- правило 7 называет порядок этапов из навыка: spec → task → failing test → code → docs → branch merge;
- «Starting a session»: новая просьба, меняющая поведение, ещё не имеет задачи — её начинают с
  `change-workflow`;
- раздел «Skills»: навык загружают снова, если его текста уже нет в контексте (например, после
  сжатия); в остальных случаях один и тот же навык дважды не грузят.

## Что не меняется

- Навык `change-workflow`: порядок этапов и их содержание.
- Без плагинов и хуков OpenCode, без «Этап:» в ответах — пользователь не выбрал.

## Затронутые документы

- `core/rules.md` — правило 7, «Starting a session», «Skills».
- `AGENTS.md` кита — блок пересобрать `./install.sh .`.
- `docs/00-overview.md`, раздел 4 — К17.

## Готово, когда

- Тест: порядок этапов из `core/skills/change-workflow/SKILL.md` дословно есть в `core/rules.md`, а
  запрета на повторную загрузку навыка без оговорки про сжатие нет.
- `uv run pytest && uv run ruff check && uv run ruff format --check` чистые.
- Пользователь проверил на GLM-5.3-flash в OpenCode, что после сжатия этапы не теряются.
