# 00. Обзор: цель, раскладка, решения

## 1. Цель

Один источник правил и навыков агентов для проектов платформенного инженера. Новый проект получает
обкатанный процесс одной командой, а улучшение правил в ките доходит до всех проектов повторным
запуском установщика.

## 2. Принципы

- Простое лучше сложного: установщик на bash, правила в markdown, без своего CLI. Тому, кто ставит
  кит, нужны только `bash`, `git` и `npx` (для CLI `skills`); тесты кита — на pytest через uv (К10).
- В ките только проверенные правила. Профиль без опыта за плечами остаётся заготовкой, пока правила
  не собраны по интервью с пользователем; правила не выдумываются.
- Сторонний код не хранится в ките: навыки ставятся по ссылке с закреплённым коммитом.
- Проект может отступать от правил кита, но записывает отступление в своём `AGENTS.md` вне
  управляемого блока; файлы кита в проекте не правятся.

## 3. Раскладка

```
core/
  rules.md          фрагмент AGENTS.md: общие правила (EN)
  skills.md         строки таблицы «ситуация → навык» (EN)
  skills.txt        сторонние навыки: URL с коммитом, по одному в строке
  skills/           свои навыки ядра, например change-workflow
  commands/         команды OpenCode: simplify, code-review, security-review
  templates/        docs/specs/README.md, TASKS.md — кладутся, только если их нет
profiles/<имя>/
  README.md         для людей: что даёт профиль (RU)
  rules.md          фрагмент AGENTS.md (EN)
  skills.md         строки таблицы «ситуация → навык» (EN)
  review.md         пункты раздела «Review checks» для команд ревью (EN)
  skills.txt        сторонние навыки профиля
  skills/           свои навыки профиля
  templates/        файлы для проекта, кладутся, только если их нет
  requires          профили, от которых зависит этот
  project.md        строки заготовки раздела проекта в новом AGENTS.md (EN)
install.sh
tests/              pytest: тесты установщика (К10)
pyproject.toml      dev-зависимости: pytest, ruff, shellcheck-py
```

В проекте после установки:

| Что | Где | В git проекта |
|---|---|---|
| правила ядра и профилей | `AGENTS.md`, блок между `<!-- platform-agent-kit:begin -->` и `:end -->` | да |
| импорт для Claude Code | `CLAUDE.md` с `@AGENTS.md`, если файла нет | да |
| навыки (свои и сторонние) | `.agents/skills/`, симлинки в `.claude/skills/` | нет |
| команды OpenCode | `.opencode/commands/` | да |
| версия кита и профили | `.agent-kit.lock` | да |
| шаблоны процесса | `docs/specs/README.md`, `TASKS.md`, если их нет | да |

## 4. Решения

| № | Решение | Суть |
|---|---|---|
| К1 | Формат (2026-10-24, пользователь) | git-репозиторий и `install.sh`. Не плагин Claude Code (не работает в OpenCode) и не шаблон copier (плохо обновляет готовые проекты) |
| К2 | Инструменты (2026-10-24) | Claude Code и OpenCode из одного источника: `AGENTS.md` общий, `CLAUDE.md` импортирует его |
| К3 | Сторонние навыки (2026-10-24, пользователь) | по ссылке с закреплённым коммитом через CLI `skills` закреплённой версии. Коммит поднимается только после чтения diff навыка |
| К4 | Профили v1 (2026-10-24, пользователь) | ядро, `helm`, `python-exporter`, `external-api`, `yandex-cloud`, `grafana` — обкатаны в работе. `cicd`, `fluxcd`, `argocd`, `otel`, `monitoring` — заготовки, правила по интервью, у каждой своя спецификация |
| К5 | Язык (2026-10-24, пользователь) | для агента (`SKILL.md`, `rules.md`, команды) — английский, в `description` навыка русские ключевые слова для срабатывания. Для людей (README, спецификации, решения, `TASKS.md`) — русский. Ядро требует от агента писать документы и коммиты проекта по-русски |
| К6 | Подход к доработкам (2026-10-24, пользователь) | часть ядра: спецификация → задача → тест → код, статусы задач, ветки `feature/NNN-slug`, мерж `--no-ff` после проверки пользователем. Процедура — навык `change-workflow`, шаблоны — `core/templates/` |
| К7 | Сборка `AGENTS.md` (2026-10-24) | управляемый блок между маркерами: ядро, затем профили в порядке аргументов, затем общая таблица «ситуация → навык». Повторный запуск заменяет только блок |
| К8 | Где лежит кит (2026-10-24, пользователь) | `~/.agents/platform-agent-kit`, каталог смонтирован с хоста |
| К9 | Сообщения коммитов (2026-10-24, пользователь) | Conventional Commits 1.0.0 (https://www.conventionalcommits.org/en/v1.0.0/): `<type>(<scope>): <описание>`. Тип на английском: `feat` и `fix` обязательны по спецификации, остальные из списка commitlint (`build`, `chore`, `ci`, `docs`, `style`, `refactor`, `perf`, `test`). Scope — область кода (в ките `core`, `install`, профиль). Описание и тело на русском, номер задачи — футер `Задача: T2.2`, несовместимое изменение — `!` перед двоеточием и футер `BREAKING CHANGE:`. Merge-коммит в том же формате, в теле ссылка на спецификацию |
| К10 | Тесты кита (2026-10-24, пользователь) | pytest через uv вместо тестов на bash: писать их на shell слишком тяжело. Dev-зависимости в `pyproject.toml`: `pytest`, `ruff`, `shellcheck-py`. Установщик остаётся на bash, чтобы ставящему не нужен был Python |
